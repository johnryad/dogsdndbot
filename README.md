# dogsdndbot

Telegram-бот, который ведёт партию D&D 5e в групповом чате (рассчитан на ~5 игроков). Ведущий язвительный, с чёрным юмором, но держит сюжет и правила. Всё по-русски и всё бесплатно: Render free, Gemini API free tier, Neon Postgres free.

## Что умеет

- **5 готовых сценариев** со своими сюжетами, NPC, монстрами, боссами и тайнами. Каждый сценарий — 4 акта. Ведущий сам переводит партию к следующему акту и выдаёт за это опыт, так что к финалу герои дорастают до 3 уровня. Можно играть и в свой мир без сценария: `/newgame мир и тон`.

  | # | Сценарий | О чём | Монстры |
  |---|---|---|---|
  | 1 | Похмелье в Гнилом Броде | свадьба, провал в памяти, похищенный жених | крысы, кобольды, гоблины, багбир |
  | 2 | Чумной квартал | город в карантине, культ «докторов» | зомби, культисты, скелеты, гули |
  | 3 | Проклятое золото «Весёлой вдовы» | пиратская карта и попугай-хам | акулы, крабы, сахуагины, мимик, капитан |
  | 4 | Туман над Вязьмищами | деревенский хоррор, воют псы, пропадают дети | волки, тени, огоньки, гули, карга |
  | 5 | Ограбление века в Медяках | ограбление банка гномов и двойная игра | стража, шпион, оживший доспех, летающие мечи, ветеран |

- **Создание героя по шагам** (`/join`): имя → класс (8 классов с описаниями) → раса (8 рас с бонусами) → характеристики (рекомендованная раскладка или ручная: каждое из чисел 15/14/13/12/10/8 ставится кнопкой) → облик и характер → предыстория. Облик и предысторию ведущий использует в рассказе и подколках.
- **Бот хранит всё об игроке**: лист героя, хиты, инвентарь, золото, опыт, состояния; журнал каждой заявки, каждого броска и каждого ответа ведущего; статистику героя (атаки, попадания, криты, позорные промахи, убийства, урон, сколько раз падал без сознания). После партии герой переходит в профиль игрока вместе с судьбой и подвигами. `/me` показывает профиль, `/log` — последние действия игрока.
- **Кубики бросает код, а не ИИ.** ИИ вызывает инструменты (`roll_dice`, `ability_check`, `attack`, `change_hp`, `add_item`, `start_combat`, `advance_plot`…) и получает готовые числа. Каждый бросок виден игрокам в свёрнутой цитате под ответом.
- **Правила и монстры** берутся из SRD 5.1 (CC-BY-4.0) через [dnd5eapi.co](https://www.dnd5eapi.co): статы монстров подтягиваются при начале боя.
- **Бой** идёт по инициативе: бот упоминает того, чей ход, монстры ходят сами, у лежащих без сознания спасброски от смерти.

## Команды

| Команда | Что делает |
|---|---|
| `/newgame` | новая партия: выбор из 5 сценариев кнопками; `/newgame мир и тон` — свой мир |
| `/join` | создать героя, бот проведёт по шагам (`/join Имя` — пропустить первый шаг) |
| `/go` | в лобби начинает приключение; потом заставляет ведущего ответить, не дожидаясь всех; в бою пропускает ход зависшего |
| `/sheet [имя]` | лист героя |
| `/status` | партия, сцена, кто заявился, очередь боя |
| `/me` | профиль игрока: текущий герой, статистика, прошлые герои |
| `/log` | последние 20 действий твоего героя с результатами бросков |
| `/roll 1d20+5 [adv\|dis]` | бросок (можно `4d6kh3`, `2d6+1d4-1`) |
| `/timeout 120` | сколько секунд ждать заявки |
| `/pause` | пауза; повторный `/pause` продолжает |
| `/leave` | выйти посреди игры: партия идёт дальше, герой ждёт |
| `/back` | вернуться в партию в любой момент, даже посреди боя (`/join` тоже возвращает) |
| `/afk Имя` | отметить пропавшего товарища: партия перестаёт его ждать |
| `/endgame` | эпилог и конец партии (с подтверждением) |
| `/here` | перенести игру в топик, где написана команда |
| `/help` | все команды |

**Топики.** Если в группе включены темы (форум), партия живёт в топике, где сделали `/newgame`: туда бот пишет всё, а сообщения и команды из других топиков игнорирует. Исключения — `/newgame` (подскажет, где идёт игра), `/here` и `/help`. Перенести игру в другой топик — `/here` прямо в нём.

Меню команд бот регистрирует в Telegram сам при запуске: при вводе `/` они всплывают с подсказками. Памятка-картинка для закрепа в чате: [docs/commands.png](docs/commands.png) (исходник — `docs/commands.html`).

Как идут ходы:
- **Вне боя** игроки пишут в чат, что делают их герои. Ведущий отвечает одним сообщением на все заявки: когда заявились все, по `/go` или по таймауту (по умолчанию 2 минуты).
- **В бою** ходят по очереди. Если игрок молчит дольше таймаута, его герой уходит в оборону.
- Сообщения, начинающиеся с `//` или `(`, — разговор вне игры, ведущий их не читает.

Кто пришёл, кто ушёл:
- Уйти можно в любой момент (`/leave`). Если это был его ход в бою, очередь сразу идёт дальше. Ведущий одной фразой убирает героя из сцены.
- Кто молчит 2 хода подряд, того бот сам отмечает отошедшим и больше не ждёт. Вернуться можно, просто написав в чат: сообщение сразу засчитается как заявка.
- Вернувшийся или новый герой посреди боя бросает инициативу и встаёт в конец очереди. Вне боя ведущий вводит его в сцену на следующем ходу.

## Что нужно завести (всё бесплатно)

1. **Бот** (у нас это @dogsdnd_bot): @BotFather → `/newbot` → получить токен. Затем выключить **Group Privacy** (в настройках бота: Groups and Channels → Group Privacy, или командой `/setprivacy` → Disable), иначе в группе бот не увидит обычные сообщения. **Allow Groups** оставить включённым. После этого добавить бота в группу (если он уже там был, удалить и добавить снова).
2. **Ключ Gemini**: [aistudio.google.com](https://aistudio.google.com) → Get API key → Create API key. **Не включать биллинг** в этом проекте Google Cloud: тогда при исчерпании бесплатного лимита API просто откажет, а не выставит счёт. Подписка Gemini Pro на лимиты API не влияет. Лимиты free tier видны в AI Studio → Rate limit. На бесплатном тарифе Google может использовать запросы для обучения моделей.
3. **База**: [neon.tech](https://neon.tech) → войти через GitHub → Create project (из сервисов нужен только Postgres database) → Connect → включить **Connection pooling** → скопировать строку вида `postgresql://user:pass@ep-xxx-pooler.us-east-2.aws.neon.tech/neondb?sslmode=require&channel_binding=require`. Строку можно вставлять как есть, таблицы бот создаст сам. Регион базы и регион сервиса на Render лучше выбрать одинаковые (у нас база в Ohio, значит и Render в Ohio).
4. **Хостинг**: [render.com](https://render.com) → войти через GitHub. Бесплатных 750 часов в месяц хватает на один сервис 24/7. Если в этом же аккаунте Render уже крутится другой бесплатный сервис, часов на двоих не хватит.

## Деплой на Render

1. New → **Web Service** → подключить репозиторий `dogsdndbot` → Language: **Docker** → Region: тот же, что у базы → Instance type: **Free**.
2. Environment → добавить переменные (таблица ниже): минимум `BOT_TOKEN`, `GEMINI_API_KEY`, `DATABASE_URL`.
3. Deploy. В логах должно появиться `ДнД: состояние храню в Postgres` и `ДнД-бот @имя запущен`.
4. **Пинговать не нужно.** На Render бот работает через вебхук: Render сам задаёт `RENDER_EXTERNAL_URL`, и бот при старте говорит Telegram присылать сообщения туда. Без сообщений бесплатный сервис через 15 минут засыпает, а первое сообщение будит его. Ответ на него придёт через 30–60 секунд, пока сервис просыпается: Telegram доставит сообщение повторно, оно не потеряется. Сервис работает только пока идёт игра, поэтому бесплатных часов хватает даже вместе с другим сервисом в том же аккаунте Render. В логе должно быть `ДнД: вебхук установлен`.
5. В чате сделать `/newgame`. В логах Render появится `ДнД: новая партия в чате -100…`. Этот id стоит вписать в `DND_ALLOWED_CHATS`, чтобы посторонние чаты не тратили ваш лимит.

## Переменные окружения

| Переменная | Обязательна | Что это |
|---|---|---|
| `BOT_TOKEN` | да | токен от @BotFather |
| `GEMINI_API_KEY` | да | ключ из AI Studio |
| `DATABASE_URL` | на Render — да | строка подключения Postgres (Neon). Без неё всё пишется в локальный SQLite, а Render стирает диск при каждом рестарте |
| `DND_ALLOWED_CHATS` | желательно | id чатов через запятую, где бот играет |
| `GEMINI_MODELS` | нет | модели по порядку. Если модель перегружена (503) или упёрлась в лимит (429), бот сразу берёт следующую, а занятую пропускает несколько минут. По умолчанию `gemini-3.5-flash,gemini-3.8-flash,gemini-3.5-flash-lite` |
| `GEMINI_RPM` | нет | не больше N запросов к ИИ в минуту, по умолчанию 8 |
| `GEMINI_THINKING` | нет | уровень «размышлений» модели: `minimal` (быстрее всего), `low` (по умолчанию: около 6 секунд на ответ), `high` (дольше, но умнее). Пустое значение отключает настройку. Модели, которые такой уровень не поддерживают, бот спрашивает без него |
| `DND_SQLITE` | нет | путь к SQLite для локального запуска, по умолчанию `dnd.sqlite3` |
| `PORT` | нет | порт веб-сервера; Render задаёт его сам |
| `WEBHOOK_URL` | нет | адрес сервиса для вебхука, если хостинг не Render (на Render берётся `RENDER_EXTERNAL_URL`). Без адреса бот работает опросом |
| `DND_POLLING` | нет | `1` — работать опросом даже на Render |

## Локальный запуск

Скопируйте `.env.example` в `.env` и заполните (файл `.env` в git не попадает). Затем:

```bash
pip install -r requirements.txt
```

```bash
python main.py
```

Локально бот работает опросом и при старте снимает вебхук. Пока вы так тестируете, бот на Render сообщений не получает. Чтобы вернуть его, перезапустите сервис на Render (Manual Deploy → Restart), и он поставит вебхук заново.

Тесты (сценарий партии без настоящих Telegram и Gemini: выбор сценария, создание двух героев по шагам, ходы с бросками, смена акта, таймаут, бой, перезапуск посреди боя, `/me`, `/log`, `/endgame`):

```bash
pip install pytest && python -m pytest tests -q
```

## Устройство

- `main.py` — веб-сервер: вебхук Telegram и health-эндпоинт `/` на Render, опрос локально.
- `dnd/bot.py` — aiogram: команды, создание героя, сбор заявок, таймеры, очередь боя, профили.
- `dnd/gm.py` — системный промпт ведущего, инструменты для ИИ, трекер боя, сжатие истории в краткое содержание.
- `dnd/scenarios.py` — 5 сценариев. Новый сценарий добавляется в словарь `SCENARIOS` по образцу.
- `dnd/rules.py` — характеристики, навыки, классы и расы по SRD, лист героя, справочник SRD.
- `dnd/dice.py` — кубики: `NdM`, `kh/kl`, преимущество и помеха.
- `dnd/llm.py` — Gemini REST: ограничение частоты, повторы, запасная модель.
- `dnd/storage.py` — Postgres или SQLite: партии, журнал, профили игроков.
